# AGENT.md — доверие к метрике проверки станочных программ

## Цель проекта
Проверить, насколько число «доля поверхности детали в допуске ±0,1 мм», которым оценивают программы
3-осевого фрезерования (в том числе написанные CAM-агентами), измеряет то, что заявлено. Найти
систематические смещения самого определения метрики и двух её реализаций: колоночной симуляции (dexel)
и точного запроса к заметаемому объёму фрезы (exact). Результат — паспорт метрики, бюджет погрешности
и оценка того, какой разнице между генераторами программ можно доверять.

## Данные и материалы
- `vendor/camverify/` — замороженный снимок измерительного кода харнесса CAM-агента (коммит 13d20b5):
  симуляция съёма материала, точный запрос, разбор G-кода, метрика. Единицы — мм; G-код задаёт кончик
  инструмента, ось инструмента +Z в системе установа. Подробности — `vendor/README.md`.
- Снимок кода не изменять; производные файлы — в `results/`.

## Как работать
- Код — в `src/`, запускать перед тем, как сообщать результат. Python проекта: `.venv/bin/python`
  (numpy, scipy, numba).
- Каждый вывод сопровождается способом его проверки.

## Проверка (ДЗ 2)
- Верификатор метрики — свойства P1–P8 и мутанты в `checks/`, методика — `METHOD.md`. Одна команда:
  `.venv/bin/python -m pytest checks -q` (снимок — `METRIC_IMPL=21a0d91|13d20b5`, по умолчанию 21a0d91).
- Шаги эксперимента: `.venv/bin/python src/hw2_experiment.py dry|smoke` — только из закоммиченного кода,
  результаты — `results/hw2_*`.
- `checks/` и `METHOD.md` не менять, чтобы тест прошёл; изменение методики — только новым разделом «Поправка N».
